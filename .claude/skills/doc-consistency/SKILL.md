# 整合性の検査

3つの成果物が互いに矛盾していないかを検査する。修正は行わず、検出結果を報告する。

## 検査対象

| 対象 | パス |
| --- | --- |
| 要求仕様書 | docs/01_要求仕様書.md |
| 仕様書 | docs/02_仕様書.md |
| 作業計画 | docs/10_作業計画.md |
| プロトタイプ | prototype/sample_v1.html |
| 議事録 | docs/minutes/ |

## 検査項目

### A. 要求から仕様への反映漏れ

要求仕様書の各 REQ について確認する。

1. 状態が「反映済」なのに、反映先の章に該当する記述がない
2. 状態が「保留」のまま、仕様書には反映されている
3. 反映先の章番号が存在しない

### B. 根拠のない仕様

仕様書の各節について確認する。

1. どの REQ からも参照されていない仕様がある
2. CLAUDE.md の「確定している設計判断」9項目に反する記述がある

新設された仕様に対応する要求がない場合、要求の起票漏れとして報告する。

### C. 数の不一致

実際に数えて照合する。前の値からの引き算で済ませない。

1. 4.6 の設問数と、4.2〜4.4 に列挙された観点の実数
2. 3.4 アンカー適用表のカテゴリ数と、4.4 のカテゴリ数
3. 3.5 識別子表のジャンル数と、4.2 のジャンル数
4. 5.3 レーダーの軸数と、各グループのカテゴリ数
5. 5.7 職種対応表の行数と、ジャンル数

### D. 議事録との突合

議事録の各項目が REQ として起票されているかを確認する。
議事録と異なる結論にしたものについて、その理由が該当 REQ の対応方針に書かれているかを確認する。

### E. プロトタイプとの乖離

サンプルHTMLは全件を収録していないため、収録範囲のみを対象にする。

1. 収録されている設問文が仕様書と一致しているか
2. アンカーの文言が 3.4 と一致しているか
3. マップの表示ルールが 5.2 と一致しているか

### F. 参照の妥当性

1. 「9章 #3」形式以外の参照が混じっていないか
2. 存在しない章・節への参照がないか。仕様書1章の章立て表に載っている章が本文に存在するか
3. 削除された ID（G1-5 など）への参照が残っていないか
4. 参照されている REQ 番号が要求仕様書に存在するか

### G. 作業計画との突合

1. 作業計画のバッチに載っている REQ が、要求仕様書に存在するか
2. 要求仕様書で状態が「保留」の REQ が、作業計画のどれかのバッチに載っているか。載っていないものは取りこぼし
3. 作業計画で「反映済」としたバッチの REQ が、要求仕様書でも反映済になっているか

## 報告形式

```markdown
## 検出結果

| # | 種別 | 箇所 | 内容 | 深刻度 |
| --- | --- | --- | --- | --- |
| 1 | 数の不一致 | 仕様書 4.6 | 設問数48と記載。実数は47 | 高 |
```

深刻度は以下で判定する。

| 深刻度 | 条件 |
| --- | --- |
| 高 | 実装に影響する。数の不一致、反映漏れ |
| 中 | 読み手が誤解する。参照切れ、記述の矛盾 |
| 低 | 表記のゆれ |

検出がゼロの場合も、何を検査したかを報告する。
